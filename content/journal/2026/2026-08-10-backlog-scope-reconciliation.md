# Backlog Scope Reconciliation

## Summary

The Abbey Root backlog had accumulated several broad ambitions, redundant
umbrella items, and tasks whose ownership had changed through later decisions.
This review reduced the inventory from 446 to 409 entries while preserving the
concrete work that still has a clear completion condition.

## Accomplishments

- Removed duplicate, superseded, and non-finishable backlog entries.
- Kept specific site, documentation, AI, and plant work in place while removing
  overlapping umbrella descriptions.
- Assigned remaining managed-host network checks to `abbey lab check`.
- Turned mobile responsiveness into a bounded viewport audit.
- Verified the generated backlog totals and Markdown formatting.

## Lessons Learned

- A backlog is more useful when every entry can eventually be proven complete.
- Project direction should not be duplicated as indefinite implementation work.
- Later architecture decisions need to reconcile the ownership language of
  older tasks, not merely add new entries beside them.

## Next Steps

- Refine conditional evaluation tasks only when their evidence thresholds are
  reached.
