# Framework Adoption Guide

## Summary

Abbey now has one practical guide for adopting the framework without copying
Abbey Root or inheriting its infrastructure and publishing configuration. The
guide combines the reference behavior established in Abbey Root, the
production standards adopted by Power Infrastructure, and the independent
project boundary validated through Bread Pitt.

## Accomplishments

- Defined the project-ownership decisions that precede adoption.
- Documented safe `abbey init` use and the separate boundary for established
  repository migration.
- Explained project metadata, planning, documentation, session, validation,
  and shared-toolkit responsibilities.
- Made optional infrastructure, DNS, site, media, and AI capabilities explicit.
- Added a finite certification checklist and authoritative reference links.
- Completed the framework-adoption backlog item.

## Lessons Learned

- Framework adoption is a contract between shared behavior and project-owned
  policy, not a copy of the reference repository.
- New-project bootstrapping and legacy migration require different safety
  boundaries.
- Real projects supply complementary evidence: reference behavior, production
  specialization, and external-project isolation.

## Next Steps

- Validate the guide during the next real framework adoption before expanding
  it with additional project types.
